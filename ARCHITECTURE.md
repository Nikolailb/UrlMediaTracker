# Architecture

## Components

Browser (React build) → KeiHub Caddy same-origin route → FastAPI → SQLite. APScheduler checks active items with bounded outbound requests. Checker selection chooses a dedicated site adapter first, then a compatible generic ToC or URL method. A typed result enters the application service; suspicious-jump policy decides whether to update the accepted latest chapter or store a pending candidate. Validated covers are files in the tracker data directory and are served only by authorized API routes.

REQ-022 makes the lifecycle status authoritative: scheduler and Check All query Ongoing only, while an owner can invoke Check now for Completed or Finished. The item API validates Finish and reopens it as Completed after lowered progress or a new verified chapter. `is_active` remains a derived legacy field for older clients and archives. The browser filters authorized items by selected status and can sort them by status; personal presets persist that selection. The additive migration maps old flags without changing progress, and archive version 2 retains the lifecycle across accounts.

Local authentication uses password hashes, one-use invites, and revocable sessions in SQLite. The browser has an HTTP-only cookie; every item query derives account and session safe-view state server-side. An admin must explicitly select another account. CSRF tokens protect mutations. `user_id` query parameters are not an authorization mechanism.

Saved filter presets belong to the selected library account and are managed through authorized API routes. Three built-ins are supplied by the server; custom preset definitions are small SQLite rows. The browser applies their category/unread/active and sort criteria to the authorized item list in either view. Safe view is enforced by the API before filtering, so no preset can expose hidden entries. Desktop chips wrap; phones use a preset modal.

The add review accepts a transient chapter URL example when the first URL is a series or ToC. The backend detects a chapter template from the example while retaining the first URL as the source and default ToC. It persists an explicit strategy override independently of the suggested preview checker. Example chapter numbers never initialize progress or latest; those values come only from their review fields or the original chapter URL. REQ-004, REQ-005.

## Checking boundary

Checkers receive canonical series/source URL, optional chapter template and ToC, accepted latest value, and bounded request settings. They return `NEW`, `UNCHANGED`, `UNSUPPORTED`, `BLOCKED`, or `FAILED`, with candidate chapter/link and diagnostic where relevant. `UNCHANGED` is terminal. Only `UNSUPPORTED` may fall through to a compatible method. Under `services/checking/`, `selector.py` chooses the method, `orchestrator.py` persists outcomes, `http.py` owns guarded direct fetching and diagnostics, `browser.py` owns the optional FlareSolverr transport, `strategies/` contains generic ToC and URL methods, and `sites/` contains one adapter module per supported site. Cover metadata parsing belongs to `covers.py` outside the checking package. FreeWebNovel uses the series' latest metadata and latest list, cross-checking the reported total; the first 40 paginated ToC entries and unrelated sidebar are not latest-chapter evidence.

A chapter URL example is an input for deriving `url_template` and `chapter_regex`, not a reading-progress value. Editing can replace that pattern without changing the ToC or progress. Generic URL probing requires a stable chapter URL template; generic ToC checking extracts actual links and never synthesizes an opaque chapter ID. If a chapter slug contains a separate long numeric ID before the visible chapter number (for example `8904631-chapter-63`), detection withholds the template. Comix's adapter reads its series-scoped `initial-data` metadata directly for latest and first chapter URLs. A preferred group can optionally use the guarded browser to inspect rendered chapter rows; metadata remains authoritative if that lookup fails. Generic ToC parsing excludes unrelated regions, groups duplicate numbers, and reports empty, contradictory, changed-layout, blocked, and truncated sources as failures rather than unchanged. REQ-016.

WebNovel's `sites/webnovel.py` adapter reads the requested book's embedded `g_data.book` catalog. It cross-checks the book ID and latest record against chapter entries, uses `chapterIndex` for progress, and builds verified links from the corresponding opaque `chapterId`. Auxiliary rows do not become chapter numbers. Its direct request may be retried through FlareSolverr only after a challenge or connection/timeout failure and only when `www.webnovel.com` is explicitly allowlisted. The catalog has a 5 MB response cap; oversized or changed layouts fail visibly. The generic ToC and URL probe strategies remain site-neutral. REQ-017.

Royal Road's `sites/royalroad.py` adapter canonicalizes a fiction to `/fiction/{id}`. It reads the complete `window.chapters` JSON in the series page rather than the rendered table, which can show only 20 rows. It validates the fiction ID, contiguous zero-based order, each chapter ID and scoped URL, and an optional declared count. The initial one-based position is `order + 1`; bonus posts count as releases. Later checks use the stored latest URL's chapter ID as an anchor, then add only entries after it. This keeps tracker numbers monotonic when older entries are stubbed; a missing anchor is a check issue. Title and chapter slugs are display/link data, not identity. Direct Cloudflare challenges use a single FlareSolverr retry only for a configured host, under a 3 MB response cap. REQ-018.

Scribble Hub's `sites/scribblehub.py` adapter canonicalizes series and chapter URLs to `/series/{id}/`. Its first ToC page is newest-first, with a declared total and explicit `order` on each row; older pages use JavaScript pagination, so routine checks need one series-page request. It cross-checks the total, selected page size, consecutive positions, same-series chapter links, and the first Read link. The latest title's chapter number can differ from the ToC position. A direct challenge uses a single guarded FlareSolverr retry for an allowlisted host, under a 1 MB response cap. Opaque chapter IDs remain in exact links only, and an unavailable intermediate link opens the ToC. REQ-019.

Item creation uses those four prose-site URL recognizers to suggest `Novel` when the category field is omitted. The add form mirrors that suggestion after preview and leaves it editable. Explicit API `null` means no category. No scraper fetch or new storage field is needed for this classification. REQ-020.

The generic ToC parser has no host-specific branches. It treats common terminal list paths as siblings of chapter links and scopes ordinary links to the series path. For chapter links outside that path, it requires a user-provided chapter URL example and derives a full same-host path pattern by replacing only the detected chapter number. An existing example-derived template can supply this pattern for older items. The advanced chapter example is saved as a ToC hint and sent to preview; the ToC path itself never supplies the outside-path pattern. The parser rejects conflicts in shared query values and applies an optional manual chapter regex to chapter URLs. It cross-checks a regex result with a visible chapter label when present. Pattern detection withholds a generated template when the path and query contain separate chapter identifiers, and the probe and Open next paths reject older saved templates with that ambiguity. Webtoons is a regression example: visible Episode 393 has a viewer URL with `episode_no=412`, so the saved `episode-(\d+)` regex extracts 393 from the real ToC link. REQ-005, REQ-011, REQ-016.

The extraction preview receives the currently selected strategy, so its reported method matches the method that a saved item will use. Saving changed detection fields invalidates the prior check status without changing accepted progress/latest, and returns a transient `check_config_changed` flag; the UI runs one immediate check for an active item and reports that outcome. With unchanged detection fields, the prior issue remains. This is a behavior change only; the status and default 360-minute interval need no new migration, and existing item intervals remain stored values. REQ-004, REQ-005, REQ-013, REQ-016.

Direct user-supplied fetch URLs require HTTP(S), public DNS results, connection to a validated address, redirect-by-redirect revalidation, and time, byte, and redirect limits. The guard covers diagnostics, metadata, ToC, probes, and covers. Never fetch loopback, RFC1918, link-local, or other reserved addresses. The general site diagnostic reports challenges directly.

Optional `services/checking/browser.py` sends one `request.get` to FlareSolverr after a site/ToC checker sees a challenge or direct connection/timeout failure and only when `FLARESOLVERR_URL` and an explicit `FLARESOLVERR_ALLOWED_HOSTS` entry are set. The Comix adapter may also request one rendered page after a direct 200 response when a preferred group's chapter link is needed; its metadata result remains valid if the browser fails. The browser transport checks the original and final URL, exact host, body size, and timeout, and allows one concurrent request. URL probing cannot use this transport. Chrome can still follow intermediate redirects and fetch subresources before the application can inspect them, so the browser container needs an independently enforced public-only egress policy before this feature is enabled on a host. FlareSolverr is optional and never exposed to users or the public network.

Both the optional local `compose.flaresolverr.dev.yml` and the pinned Pi stack in `ops/pi-browser/compose.yaml` put FlareSolverr on an internal-only Docker network. A dual-network gateway exposes its API only to host loopback and provides a browser HTTP proxy. The proxy resolves each destination, rejects any DNS answer that is not globally routable, and connects to a validated literal address; it permits HTTP GET/HEAD and HTTPS CONNECT only. FlareSolverr has no direct default route, so Chrome subresource and redirect requests must pass through this proxy. On the Pi, the tracker host Compose sets `FLARESOLVERR_URL` to loopback and explicitly allowlists approved hosts. Docker reports that Pi kernel memory limits are unavailable; the application serializes browser requests and operators must watch RAM and swap. REQ-015.

## Storage and operations

SQLite remains the only database. Alembic owns additive schema migrations; startup `create_all` is not a migration. Index items by owner, sensitivity, and check dates. The portable account archive is versioned, includes custom presets, and excludes credentials, sessions, invites, and host secrets. Encrypted restic snapshots include consistent SQLite data, cover files, configuration, and matching deployment revision.

The Pi remains KeiHub-managed: separate tracker Compose project, Caddy HTTPS on LAN/VPN, CI-gated candidate build, verified pre-upgrade backup, migration, readiness test, and paired rollback. The documented DB is `/srv/keihub/data/tracker/main.db`; inspect the live mount before edits. Add persistent covers beneath the tracker data root and verify backup inclusion. Do not introduce Redis, PostgreSQL, object storage, or required cloud identity. The optional browser stack is a separate Compose project under `/srv/keihub/sources/tracker-browser`; it changes no schema and can be stopped independently. Adding another browser-allowed site requires evidence that direct ToC fetching is blocked, a successful bounded browser parse, and another Pi resource review.
